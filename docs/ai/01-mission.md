# Mission

This document defines the mission of the WIL.DEV project.

Every AI assistant contributing to this repository must understand and follow the principles described here before writing any code.

This document is the foundation for every technical decision.

---

# Project

Project Name

WIL.DEV

Repository Type

Static Website

Owner

Wilson Cavalcante

---

# Mission

Build a long-term professional platform that represents the work, experience and engineering philosophy of Wilson Cavalcante.

The objective is not to create a portfolio.

The objective is to build a professional technical brand.

Every implementation must strengthen that brand.

---

# What This Website Is

This website is:

- a professional brand;
- a technical knowledge platform;
- a software engineering showcase;
- a collection of enterprise case studies;
- a publication platform;
- a long-term digital identity.

Every feature must reinforce these goals.

---

# What This Website Is Not

This website is NOT:

- an online résumé;
- a personal blog;
- a CMS;
- an admin panel;
- a dashboard;
- a generic portfolio template;
- a UI experiment.

Never implement features that move the project toward those directions.

---

# Target Audience

The primary audience includes:

- Software Architects
- Technical Leaders
- Engineering Managers
- CTOs
- Technology Directors
- Enterprise Companies
- Adobe Experience Cloud Professionals
- Recruiters for Senior Technical Positions

The website is written for technical professionals.

Avoid unnecessary simplifications.

---

# Communication Style

The communication style must be:

Professional.

Technical.

Objective.

Clear.

Elegant.

Confident.

Never exaggerated.

Never promotional.

Never sensationalist.

The website should demonstrate expertise through quality, not marketing language.

---

# Core Values

Every implementation should reinforce the following values.

Engineering Excellence

Technical Leadership

Knowledge Sharing

Continuous Learning

Long-Term Thinking

Software Craftsmanship

Simplicity

Maintainability

Performance

Accessibility

---

# Long-Term Vision

The project is expected to evolve over many years.

The architecture must support continuous growth without requiring major redesigns.

Every implementation should consider future maintainability.

Avoid short-term solutions.

---

# Business Objective

The website exists to:

demonstrate expertise;

publish technical knowledge;

show enterprise experience;

build credibility;

strengthen professional reputation;

serve as the central digital identity of the author.

Everything else is secondary.

---

# Success Criteria

A successful implementation makes the website:

easy to navigate;

easy to maintain;

easy to expand;

fast;

accessible;

professional;

technically consistent.

---

# Engineering Mindset

Every contribution should follow this mindset.

Think long-term.

Build reusable solutions.

Reduce complexity.

Prefer clarity over cleverness.

Prefer consistency over novelty.

Always leave the codebase better than it was before.

---

# AI Mission

While working on this project, your mission is not simply to generate code.

Your mission is to help build and maintain a professional software engineering platform that will remain relevant, maintainable and technically consistent for many years.

Every decision should contribute to that mission.

If a proposed implementation conflicts with this objective, choose the solution that better preserves the long-term quality of the project.
